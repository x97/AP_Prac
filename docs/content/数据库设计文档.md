## 0. 双库架构（v4.0）

| 数据库 | 定位 | 当前内容 | 是否含知识点 |
|---|---|---|---|
| `psychology_exam.db` | 题库：试卷 / 题目 / 选项 / 答案 / 评分标准 | 31 份卷、2,876 题 | 否（exam-only） |
| `psychology_knowledge.db` | 知识点库：书 / 章节 / 知识点 / 概念 / 去重 | 1 学科、2 本书、399 个 section、1,538 条 KP、1,105 条概念 | 是 |

分工原则：

1. **题库不重新引入知识点表**。`ap_exam.db` 继续保持 2026-10-26 精简后的 exam-only 结构。
2. **知识点抽取独立建库**。`ap_knowledge.db` 按“书 → section → knowledge_point”组织，便于换书、换学科、重跑抽取。
3. **两库通过 `subject_id` 对齐**。当前均为 `psychology`；`ap_knowledge.db.subjects` 是 `ap_exam.db.subjects` 的镜像，核心三列保持一致。
4. **跨库关联不建外键**。SQLite 不支持跨库外键；题目 ↔ 知识点用应用层映射表（如 `question_kp_links`）或视图实现，ID 约定见 §4。
5. **知识点库的完整设计见 Part B（§11–§19）与附录 C**。

## 1. 设计目标

1. **一道题只存一份**。同一道题可以同时属于真题卷、某个教材单元的练习、某个错题集，靠关系表引用，不复制数据。
2. **内容类型可扩展，但当前只保留三种**：真题 / 模拟题 / 单元练习。教材课后题与章末 Review Questions 统一归入单元练习；将来如需新类型，往字典表加一行即可，不改表结构。
3. **教材 / 单元 / 知识点可挂接**。试卷可以针对某个单元，题目也可以单独挂到某个单元；两者是多对多。
4. **主观题评分细则结构化**。每个评分点单独一行，带分值、评分标准、判分规则、正反例，便于 AI 逐点评分。
5. **图片素材可挂在题目或选项上**。选择题的图表、整页扫描、按选项拆分的图片都能表达。
6. **扩展只加列、不重建表**。此前所有新增字段都通过 `ALTER TABLE ADD COLUMN` 完成。

## 2. 总体结构

按三层拆分：

```
┌──────────────── 分类 / 关联层 ────────────────┐
│  subjects   paper_types   textbooks           │
│  curriculum_units (树)                         │
│  tags (topic / skill / difficulty)            │
│  paper_units   question_units   question_tags │
└───────────────────────────────────────────────┘
                     │
┌──────────────────── 容器层 ───────────────────┐
│  papers ──< paper_sources                     │
│  collections ──< collection_items             │
└───────────────────────────────────────────────┘
                     │
┌──────────────────── 内容层 ───────────────────┐
│  questions ──< options                        │
│            ├──< assets                        │
│            └──  frq_rubrics ──< rubric_parts  │
└───────────────────────────────────────────────┘
```

### ER 关系图

```
subjects 1 ──── N papers 1 ──── N questions 1 ──── N options
                   │                 │
                   │                 ├──── N assets            (题目级或选项级)
                   │                 ├──── 1 frq_rubrics ──< N rubric_parts
                   │                 ├──< question_units >── curriculum_units
                   │                 └──< question_tags  >── tags
                   │
                   ├──< paper_units >── curriculum_units ──< textbooks
                   ├──< paper_sources
                   └──< collections ──< collection_items >── questions
```

关系说明：

- 一对多：`papers → questions → options`，`questions → assets`，`frq_rubrics → rubric_parts`。
- 一对多（可选）：`questions → frq_rubrics`，只有主观题有。
- 多对多：试卷↔单元、题目↔单元、题目↔标签、集合↔题目。
- 树形自关联：`curriculum_units.parent_id → curriculum_units.unit_id`。

### 3.5 questions（题目）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| question_id | TEXT | PK | 如 `psychology-2019-mcq-017`、`psychology-2025-frq-1-001` |
| paper_id | TEXT | NOT NULL, FK → papers | 所属试卷 |
| section | TEXT | NOT NULL | `MCQ` / `FRQ`（目前是自由文本） |
| number | INTEGER | NOT NULL | 卷内题号 |
| stem | TEXT | NOT NULL | 题干（FRQ 含完整材料与 Source） |
| context | TEXT | | 共用材料，如 “Questions 62-64 are based on the following.” |
| page_start | INTEGER | | 起始页（PDF 物理页码） |
| page_end | INTEGER | | 结束页 |
| correct_answer | TEXT | | MCQ 为 `A`–`E`；FRQ 为 NULL |
| answer_text | TEXT | | FRQ 评分标准全文（原始文本，兜底用） |
| subject_id | TEXT | NOT NULL, FK → subjects | 学科 |
| form | TEXT | | 卷型，2025 用于区分 `Set 1` / `Set 2` |
| source_file | TEXT | | 该题来源文件（与 paper_sources 呼应） |
| answer_source | TEXT | | 答案来源：`official`（答案表）/ `official_highlight`（CB 题库绿色标注）/ `book_answer`（Barron's 答案解析）/ NULL（FRQ） |
| answer_confidence | TEXT | | 预留字段（当前无 AI 推断答案） |
| question_fingerprint | TEXT | | `sha1(normalize(stem)+normalize(options))`，用于跨卷重复题检测/合并 |

唯一约束：`UNIQUE(paper_id, section, number)`。
索引：`idx_questions_fingerprint(question_fingerprint)`。
索引：`idx_questions_paper(paper_id, section, number)`。

示例（选择题）：

```json
{

  "paper_id": "psychology-ap-2019",
  "section": "MCQ",
  "number": 17,
  "stem": "A person uses the availability heuristic to",
  "correct_answer": "B",
  "page_start": 14,
  "page_end": 14
}
```

```json
{
  "question_id": "psychology-2025-frq-1-001",
  "paper_id": "psychology-ap-2025",
  "section": "FRQ",
  "number": 1,
  "form": "Set 1",
  "stem": "Using the source provided, respond to all parts of the question. ...",
  "answer_text": "General Considerations ... (完整评分标准)",
  "correct_answer": null

```

### 3.7 assets（图片素材）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| asset_id | TEXT | PK | 如 `2025-fig-016` |
| question_id | TEXT | NOT NULL, FK → questions | 所属题目 |
| option_label | TEXT | FK (question_id, option_label) → options | NULL = 题目级；`A`–`E` = 选项级 |
| kind | TEXT | NOT NULL | `figure` 紧贴图形 / `table` 表格 / `option` 选项图 / `page` 整页 |
| path | TEXT | NOT NULL | 相对项目根目录，如 `assets/psychology/images/2025/fig_q016.png` |
| page | INTEGER | | 来源 PDF 页码 |
| bbox | TEXT | | JSON 数组 `[x0, y0, x1, y1]`，相对来源页面的比例坐标（左上原点） |
| description | TEXT | | 图表/选项图下方的原文图案说明（无则为 NULL） |

索 引：`idx_assets_question(question_id)`。

要点：

- `option_label IS NULL` 表示整题配图；`option_label='B'` 表示只属于 B 选项。
- 保存的图片可能被等比缩放到最大宽度 1100/1600，`bbox` 记录的是**原图上的裁剪范围**，不是保存后文件的像素尺寸。

示例：

```json

  "question_id": "psychology-2025-mcq-098",
  "option_label": "B",
  "kind": "option",
  "path": "assets/psychology/images/2025/fig_q098_B.png",
  "page": 17,
  "bbox": "[0.552, 0.431, 0.752, 0.5]"

```

### 3.8 frq_rubrics（主观题评分标准）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| rubric_id | TEXT | PK | `<subject_id>-rub-<年份>-<题型>-<序号>`，如 `psychology-rub-2025-frq-1-001` |
| question_id | TEXT | NOT NULL, UNIQUE, FK → questions | 一题一份 |
| total_points | INTEGER | | 总分 |
| general_considerations | TEXT | | 总则（拼写、扣分、矛盾处理等） |
| format | TEXT | | `parts_2025` / `legacy_points` |

两种格式：

- `parts_2025`：2025 年官方格式，按 Part A–F / B(i) 等拆分，含 0/1/2 多级标准。
- `legacy_points`：2018/2019 格式，按 Point 1…N 拆分，每点 1 分，含 “Response must include…” 标准与 Score / Do NOT score 示例。

| title | TEXT | | `Research Method` / `Control condition` |
| max_points | INTEGER | | 该点满分 |
| criteria | TEXT | | JSON 数组，见下 |

### 3.17 question_keywords / question_keypoints（题目 ↔ 知识点）

`question_keywords`：记录知识点在题目文本中的匹配位置，供前端做可点击高亮。当前实现是**每个字段只记录第一次出现**（不是每一次出现），以避免同一选项内重复高亮和重复计数。

| 字段 | 类型 | 说明 |
|---|---|---|
| question_id | TEXT FK | 题目 |
| kp_id | TEXT FK | 知识点 |
| field | TEXT | `stem` / `optionA` … `optionE` |
| surface | TEXT | 原文中的写法 |
| start, end | INTEGER | 在字段中的字符偏移 |

主键 `(question_id, kp_id, field, start)`；当前 4,969 条。

`question_keypoints`：题目与知识点的**全量**聚合关系（`hits` = 匹配到的字段数，不区分出现位置），主键 `(question_id, kp_id)`；当前 4,456 条。它适合做“出现过”的检索，**不适合直接当相似题推荐**：其中 2,491 条（55.9%）只出现在干扰选项里。

推荐使用视图 `v_question_kp_relevance` 做相似题/相关性判断：

| 字段 | 含义 |
|---|---|
| stem_hits | 在题干中出现的次数 |
| correct_hits | 在正确选项中出现的次数 |
| distractor_hits | 在错误（干扰）选项中出现的次数 |
| relevance_score | `3 × correct_hits + 2 × stem_hits`（干扰项权重 0） |
| relevance | `correct` / `stem` / `distractor` |

```sql
-- 相似题：只取题干或正确选项中的出现
SELECT q.question_id, q.stem, r.relevance, r.relevance_score
FROM v_question_kp_relevance r
JOIN questions q ON q.question_id = r.question_id
WHERE r.kp_id = 'psychology-kp0049'
  AND r.relevance IN ('correct', 'stem')
ORDER BY r.relevance_score DESC, q.paper_id, q.number;
```

`questions.primary_unit_id` / `primary_chapter_id`：2026-10-26 起按 `v_question_kp_relevance` 的 **strict 口径**重算（只算 `correct` / `stem`，correct 权重 3、stem 权重 2；不使用干扰项）。CB 题若有 `question_units.is_primary=1`，Unit 固定取该行；Chapter 用该 Unit 内的 strict 投票。当前 2,485 题中 2,126 题有 Unit、1,134 题有 Chapter；没有 strict 证据的题保持 NULL，不再用干扰项兜底。

视图当前计数：`correct` 923 对、`stem` 1,042 对、`distractor` 2,491 对。

### 3.19 题目解析关联（ap_knowledge.db，v4.8 全库）

> §3.10–§3.18 是已删除表的历史设计；本节是当前新增的“题目 ↔ 知识点/关键字”关联，**表在 `ap_knowledge.db`，不在 `ap_exam.db`**。`question_id` 是逻辑引用，不建跨库外键；`kp_id` 仍受 `knowledge_points` 外键约束。

| 表 | 作用 |
|---|---|
| `question_analysis` | 每道题一条分析状态：`linked` / `needs_review` / `no_match` / `skipped`，记录模型、prompt 版本和备注 |
| `question_concept_links` | **题目 ↔ 规范概念（当前主目标层）**：`core` / `supporting` / `confusable`，带 `option_label`、confidence、evidence |
| `concept_relations` | 概念关系：上下位 / 整体-部分 / 相关 / 同名异义 |
| `question_kp_links` | 题目 ↔ 来源知识点（legacy/UI 兼容） |
| `question_keywords` | 题目里实际出现的关键字：原文 `surface`、归一化、可选 `kp_id` / `concept_id`、`role`、`location`、`option_label` |

字段要点：

- `question_concept_links.relation_type`：`core` / `supporting` / `confusable`；`confusable` 必须带 `option_label`；唯一键 `(question_id, concept_id, relation_type, IFNULL(option_label,''))`。
- `question_kp_links.relation_type`：`core` / `supporting` / `confusable`；`confusable` 必须带 `option_label`。
- `question_kp_links.evidence`：核心知识点的题干/正确选项原文证据。
- `question_keywords.role`：`core` / `supporting` / `mentioned` / `distractor`。
- `question_keywords.location`：`stem` / `context` / `correct_option` / `option`；`option` 必须带 `option_label`。
- `question_keywords.kp_id` 可为 NULL：表示这是题目里的真实术语，但知识库暂未收录（如 `Animism`、`Preoperational`）。
- `question_keywords.concept_id` 是概念层新增列；旧页面继续读 `kp_id`，新逻辑可读 `concept_id`。
- `kp_aliases` 新增 `match_mode`（`insensitive` / `case_sensitive`），用于 `DID`、`CNS`、`IRB` 等缩写，避免 `DID` 匹配普通单词 `did`。

关联原则：

1. **关键字 ≠ 知识点**。关键字是题目文本里出现的术语；知识点是正确解答必需的概念。
2. **核心知识点从正确答案倒推**，1 个为常态、最多 2 个；干扰项里的术语只进 `confusable`，不能进 `core`。
3. **不强行映射**。知识库没有的概念写 `needs_review` / `no_match`，并在报告中列出待补概念。
4. **候选检索**：Barron 章节用 `Chapter N` 全部 KP + 别名精确匹配；CB Unit 用 `Unit N` 池 + 子小节；无章节试卷用本地 BM25 检索。模型只从短 key（`C01`…）中选择。
5. **页面展示**只保留核心/辅助/易混淆知识点；不显示“相关术语”“干扰项术语”等额外区块。未收录核心概念只在“本题核心概念暂未收录”提示里出现。
6. **批量执行**用 `_tools/link_all_question_kps.py`，按试卷 checkpoint；中断后重跑会跳过已完成题目。

当前覆盖：31 份试卷、2,848 道 MCQ 全部有 `question_analysis`（2,754 linked / 90 needs_review / 4 no_match）；`question_kp_links` 7,372 条（3,063 core / 1,474 supporting / 2,835 confusable），`question_keywords` 14,209 条；概念层 `question_concept_links` 7,371 条 / 2,837 题（3,063 core / 1,474 supporting / 2,834 confusable，2,820 题有 core）。`kp_aliases` 1,781 条；1,105 条规范概念覆盖全部 1,538 个 KP；209 条概念关系（上下位/整体-部分/相关/同名异义）。逐卷产物在 `data/content/psychology/extraction/question_analysis_<paper>.json` 与 `data/content/psychology/reports/question_analysis/`，汇总在 `data/content/psychology/reports/question_analysis/question_analysis_all_report.md`。生成脚本为 `_tools/link_question_kps.py`（`--export-only` 可从数据库重建 JSON/报告），批量脚本为 `_tools/link_all_question_kps.py`，概念关联见 `_tools/link_myers_concepts.py`，流程说明见 `../prompts/03_question_concept_linking.md`（旧 KP 版见 `../prompts/legacy/01_question_kp_linking.md`）。

建表 DDL 以 `_tools/migrate_question_analysis.py` 为准；别名生成见 `_tools/build_kp_aliases.py`。

### 6.7 AI 评分工作流

1. 取出题目与评分细则：

```sql
SELECT q.question_id, q.stem, fr.total_points, fr.general_considerations,
       rp.label, rp.title, rp.max_points, rp.criteria,
       rp.decision_rules, rp.examples_positive, rp.examples_negative, rp.notes
FROM questions q
JOIN frq_rubrics fr ON fr.question_id = q.question_id
JOIN rubric_parts rp ON rp.rubric_id = fr.rubric_id
WHERE q.question_id = 'psychology-2025-frq-1-001'
ORDER BY rp.sort_order;
```

2. 逐评分点构造提示词：`criteria`（该点各级标准）+ `decision_rules` + 正反例。
3. 要求模型对每个 `part` 返回 `{label, points, rationale}`。
4. 汇总得分，并与 `total_points` 对账。

两种格式的提示方式：

- `parts_2025`：按 criteria 的 0/1/2 级别判分。
- `legacy_points`：每个 Point 只有“满足 / 不满足”，依据 “Response must include…” 与正反例判定 0 或 1。

## 7. 常用查询

**按试卷取选择题及选项**

```sql
SELECT q.question_id, q.number, q.stem, q.correct_answer,
       o.label, o.content, o.is_correct
FROM questions q
LEFT JOIN options o ON o.question_id = q.question_id
WHERE q.paper_id = 'psychology-ap-2019' AND q.section = 'MCQ'
ORDER BY q.number, o.sort_order;
```

**取某题的配图**

```sql
SELECT kind, option_label, path
FROM assets
WHERE question_id = 'psychology-2025-mcq-016'
ORDER BY kind, option_label;
```

**按单元取题**

```sql
SELECT q.question_id, q.stem
FROM questions q
JOIN question_units qu ON qu.question_id = q.question_id
WHERE qu.unit_id = 'psychology-barrons-2026-c1'
ORDER BY q.question_id;
```

**按标签取题**

```sql
SELECT q.question_id, q.stem
FROM questions q
JOIN question_tags qt ON qt.question_id = q.question_id
WHERE qt.tag_id = 'psychology-skill-sp2';
```

**每套卷的题量**

```sql
SELECT paper_id, section, COUNT(*) AS n
FROM questions
GROUP BY paper_id, section
ORDER BY paper_id, section;
```

**检查评分点分值是否与总分一致**

```sql
SELECT fr.question_id, fr.total_points, SUM(rp.max_points) AS sum_parts
FROM frq_rubrics fr
JOIN rubric_parts rp ON rp.rubric_id = fr.rubric_id
GROUP BY fr.rubric_id
HAVING sum_parts != fr.total_points;
```

## 9. 已知限制与待办

1. **2018 FRQ 2 评分标准不完整**：原始 PDF 只到 Point 3（Superordinate Goals），后续 Metacognition、Token Economy、Part C 的评分点在源文件中缺失。当前 `total_points=3` 反映的是文件内容，不是该题的真实满分。
2. **两种评分格式并存**：2018/2019 为 `legacy_points`（每点 1 分、单一标准），2025 为 `parts_2025`（多级标准）。AI 评分逻辑需按 `format` 分支。
3. **2018/2019 缺 Topic / Skill 元数据**：可后续从 2019 的 Question Descriptors 表补齐；2018 卷未见对应表。
4. **`assets.bbox` 是来源页面的比例坐标**，不是保存图片的像素坐标；保存文件可能被缩放。

8. **外键默认不强制**，需每连接执行 `PRAGMA foreign_keys = ON;`。
9. **2018/2019 文本来自 OCR**，长题干可能有少量识别错误；2025 来自高清截图，质量更高。
10. **知识点定义覆盖率（历史 468 KP 口径）**：旧口径下 42 个 Key Terms 只在列表出现、正文没有可用定义；复核报告归档在 `_archive/legacy_knowledge_pipeline/kp_extraction_report.csv`。当前 `ap_knowledge.db` 的 1,538 个 KP（Barron 860 + Myers 678）均有定义摘要。

# Part B：知识点数据库（ap_knowledge.db）

> 本部分为 **v4.0（2026-10-26）** 新增。`ap_exam.db` 继续保持 **exam-only**；知识点抽取写入独立数据库 `ap_knowledge.db`。两库通过 `subject_id`、`book_id` 逻辑关联；SQLite 不支持跨库外键，跨库一致性由应用层或视图保证。

## 11. 设计目标

1. **书无关**。任何学科、任何书型（教材、复习书、专著、词典、练习册）都使用同一套表结构；差异放在 `books.book_type` / `subjects.discipline` 等字段，不靠建新表解决。
2. **结构标准化**。目录小节 = 知识点块；正文子标题 = 块内条目。目录有几个知识点小节，就生成几个 section block；子标题不得合并、不得丢弃。
3. **原文可追溯**。每条知识点必须有 `book_id + section_id + source_page + definition_quote + quote_hash`；能回到原书定位。
4. **不臆造**。定义、研究者、实验只能来自本节原文；书中没有就写 `NULL` 或 `not_mentioned`，禁止用常识补全。
5. **通俗解释标准化**。`plain_en` 统一用简单英文，**1–10 个英文单词**，不得含中文，不得引入新事实。
6. **去重强制**。精确重复的核心定义必须为 0 组，才能从 staging 提升到正式表；同名不同义不得按名称误删。
7. **可重跑**。确定性 ID、staging 表、`ingestion_runs` 记录每次运行的提示语版本、模型、GATE 结果与统计。
8. **多书可扩展**。`subjects → books → sections → knowledge_points` 四级归属；跨书同概念用 `concept_clusters` 关联，保留各书出处，不删除。

## 12. 总体结构

```
subjects 1 ──── N books 1 ──── N sections 1 ──── N knowledge_points
                                  │                    ├──< kp_researchers
                                  │                    ├──< kp_experiments
                                  │                    ├──< kp_aliases
                                  │                    └──< kp_relations >── knowledge_points
                                  │
                                  ├──< section_texts
                                  └──< section_researchers

concept_clusters 1 ──── N knowledge_points
ingestion_runs 1 ──── N validation_issues
```

关系说明：

- `subjects → books`：一本书只归一个学科；多学科合集按主要学科归类，必要时拆成多本 `book`。
- `books → sections`：`sections.parent_id` 自关联，表达 Unit → Chapter → Section → Subheading 的树。
- `sections → knowledge_points`：一个目录小节是一个知识点块；块内每条概念一行 `knowledge_points`。
- `knowledge_points → kp_researchers / kp_experiments`：只记录本节明确出现、且与该概念直接相关的人名/实验。
- `section_researchers`：本节提到但无法绑定到具体概念的姓名/实验，放在节级，避免硬挂。
- `concept_clusters`：跨书/跨章的同概念聚类；不删除任何一条 KP，只建立关联。
- `ingestion_runs → validation_issues`：每次抽取的 GATE 结果与问题清单。

## 13. 学科归类（subjects）

### 13.1 现有 subjects 表

`ap_exam.db` 当前只有 1 行：

| subject_id | name | name_zh |
|---|---|---|
| psychology | AP Psychology | AP 心理学 |

`ap_knowledge.db` 的 `subjects` 表保留这三个核心字段，并增加 `discipline`、`exam_code`、`description`、`created_at`，用于更细的归类。两库的 `subject_id` 必须一致。

### 13.2 归类规则

新书入库时按以下顺序判定学科，**不得只看书名中的一个词**：

1. **元数据信号**：书名、副标题、作者、出版社、ISBN、语言、版次。
2. **结构信号**：目录中的 Unit/Chapter 名称、课程框架、考试说明、学科术语密度。
3. **考试信号**：封面/版权页/目录中出现的考试名称（AP、IB、A-Level、GRE、考研等）。
4. **匹配 `subjects` + `subject_aliases`**：先按 `subject_id`、`name`、`name_zh`、别名精确匹配；再按关键词匹配。
5. **置信度规则**：
   - 至少 2 个独立信号一致，才可 `classification_status='auto'`；
   - 只有 1 个信号，或两个信号冲突，标 `needs_review`，不得自动写正式表；
   - 无法匹配任何学科，创建新 `subject_id`（小写 slug），标 `needs_review`，并记录证据。
6. **证据留存**：`books.classification_evidence` 存 JSON，至少包含命中的信号、匹配到的 `subject_id`、置信度、判定时间。
7. **人工确认**：`classification_status='confirmed'` 只能由人工或明确规则升级；自动流程不得把 `needs_review` 改成 `confirmed`。

### 13.4 新书归类流程

```text
1. 读取封面/版权页/目录/前言。
2. 提取书名、作者、出版社、ISBN、语言、版次、考试名称。
3. 在 subjects / subject_aliases 中匹配。
4. 计算信号数与冲突数。
5. 写 books 行：
   - 2+ 信号一致 → classification_status='auto'
   - 1 个信号或冲突 → 'needs_review'
   - 无匹配 → 新建 subject_id，'needs_review'
6. 写 classification_evidence。
7. 只有 classification_status IN ('auto','confirmed') 的书才允许进入正式抽取；
   'needs_review' 只能写 staging，等待人工确认。
```

## 15. 提取流水线与 GATE

完整提示语见 `../prompts/01_book_kp_extraction.md`。数据库侧只接受通过以下 GATE 的运行：

| GATE | 通过条件 | 失败动作 |
|---|---|---|
| G0 书籍可读 | 文本层可用，或 OCR 置信度达标 | 停止 |
| G1 结构地图 | 目录/正文标题逐条对账，差异有报告 | 停止 |
| G2 节边界 | 每节 page_start/page_end 有效，无跨节 | 停止 |
| G3 子标题覆盖 | 每个 subheading 至少 1 条 KP | 停止 |
| G4 原文定义 | `definition_quote` 逐字匹配率 100% | 停止 |
| G5 通俗解释 | `plain_word_count` 全部 1–10 | 停止 |
| G6 去重 | 全库精确重复 = 0 组 | 停止 |
| G7 写库 | staging → 正式表事务成功，FK/唯一约束通过 | 回滚 |

## 16. 去重规则

去重是**最后一步**，且必须基于全书统一 registry，不能只做单章去重。

1. **精确重复**：`normalized(definition_quote)` 完全相同。
   - 同一概念：保留最早一条，其余 `duplicate_of` 指向保留条目。
   - 一句话同时定义两个概念：拆成各自的概念定义；无法拆分时合并为一条，用 `covers_concepts` 记录两个概念。
   - 同名不同义：保留两条，`kp_relations.relation_type='homonym'`，不得按名称删除。
2. **近似重复**：同一概念且相似度 ≥ 0.90 → `near_duplicate`，人工复核；不得自动删除。
3. **同名不同定义**：保留两条，标 `same_name_different_definition`；教材跨章复现通常属于此类。
4. **跨书重复**：不删除；用 `concept_cluster_id` 关联，保留各书出处。
5. **最终门禁**：`SELECT COUNT(*) FROM (SELECT quote_hash FROM knowledge_points WHERE quote_hash IS NOT NULL GROUP BY quote_hash HAVING COUNT(*)>1)` 必须为 0。

去重报告至少输出：精确重复组数（前/后）、拆分共享定义数、同名概念对及分类、近重复对及相似度。

## 17. 写入与幂等

1. **staging 优先**：先写 `staging_sections` / `staging_knowledge_points`（结构同正式表，或加 `run_id` 列），全部 GATE 通过后再事务性插入正式表。
2. **确定性 ID**：
   - `book_id = <subject_id>-<publisher-slug>-<edition>`
   - `section_id = sha1(book_id + path)[:16]`
   - `kp_id = sha1(book_id + section_id + name_normalized + quote_hash)[:16]`
3. **幂等 upsert**：同一 `book_id` 重跑时，按 `book_id + section_id + name_normalized + quote_hash` 判重；已有且未变则跳过，变化则写新版本（可加 `supersedes_kp_id`）。
4. **备份**：写库前 `.backup` 或复制数据库；正式表提升前保留 staging。
5. **事务**：`BEGIN IMMEDIATE; ... COMMIT;`；任一步失败 `ROLLBACK`。
6. **运行记录**：每次运行写 `ingestion_runs`，包含 `prompt_version`、模型、GATE 结果、统计。

## 18. 常用查询

**某书的所有知识点块**

```sql
SELECT s.section_id, s.heading, s.pdf_page_start, COUNT(kp.kp_id) AS kp_count
FROM sections s
LEFT JOIN knowledge_points kp ON kp.section_id = s.section_id
WHERE s.book_id = 'psychology-barrons-2027' AND s.excluded = 0
GROUP BY s.section_id
ORDER BY s.path;
```

**某节的原文与知识点**

```sql
SELECT kp.name, kp.definition_quote, kp.plain_en, kp.source_page
FROM knowledge_points kp
WHERE kp.section_id = ?
ORDER BY kp.kp_id;
```

**全库精确重复检查**

```sql
SELECT quote_hash, COUNT(*) AS n
FROM knowledge_points
WHERE quote_hash IS NOT NULL
GROUP BY quote_hash
HAVING n > 1;
```

**同名概念跨块检查**

```sql
SELECT name_normalized, COUNT(*) AS n, GROUP_CONCAT(section_id)
FROM knowledge_points
GROUP BY name_normalized
HAVING n > 1
ORDER BY n DESC;
```

**某书的 GATE 结果**

```sql
SELECT run_id, status, gates_json, stats_json
FROM ingestion_runs
WHERE book_id = 'psychology-barrons-2027'
ORDER BY started_at DESC;
```

CREATE VIEW v_question_kp_relevance AS
SELECT
  qk.question_id,
  qk.kp_id,
  SUM(CASE WHEN qk.field='stem' THEN 1 ELSE 0 END) AS stem_hits,
  SUM(CASE WHEN qk.field='option'||q.correct_answer THEN 1 ELSE 0 END) AS correct_hits,
  SUM(CASE WHEN qk.field LIKE 'option%'
      AND (q.correct_answer IS NULL OR qk.field <> 'option'||q.correct_answer)
      THEN 1 ELSE 0 END) AS distractor_hits,
  SUM(CASE WHEN qk.field='option'||q.correct_answer THEN 3
           WHEN qk.field='stem' THEN 2 ELSE 0 END) AS relevance_score,
  CASE
    WHEN SUM(CASE WHEN qk.field='option'||q.correct_answer THEN 1 ELSE 0 END) > 0 THEN 'correct'
    WHEN SUM(CASE WHEN qk.field='stem' THEN 1 ELSE 0 END) > 0 THEN 'stem'
    WHEN SUM(CASE WHEN qk.field LIKE 'option%' THEN 1 ELSE 0 END) > 0 THEN 'distractor'
    ELSE 'other'
  END AS relevance
FROM question_keywords qk
JOIN questions q ON q.question_id = qk.question_id
GROUP BY qk.question_id, qk.kp_id;
