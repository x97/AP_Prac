# 新增 PDF 试卷解析与入库流程

> 适用：把一份新的 AP 试卷 / 题库 PDF 解析进 `data/content/<subject>/<subject>_exam.db`，再构建并激活 Release。  
> 不再使用 `AP_exam/`、根目录 `ap_exam.db` 或静态刷题页。

---

## 0. 一句话流程

```text
PDF / 答案 / rubric
→ 解析成中间 JSON（data/content/<subject>/extraction/）
→ QA 报告（data/content/<subject>/reports/）
→ 写科目源库 <subject>_exam.db
→ 概念关联（可选）
→ AI 解析（可选）
→ 构建合并 Release
→ 校验 → 激活
```

---

## 1. 目录与命名

### 1.1 源文件

```text
assets/<subject_id>/papers/<year>/<file>.pdf
assets/<subject_id>/papers/<year>/<answer>.pdf
assets/<subject_id>/papers/<year>/<rubric>.pdf
assets/<subject_id>/images/...
assets/<subject_id>/books/...
```

### 1.2 解析产物

```text
data/content/<subject_id>/extraction/
  <source>_<paper_id>.json       # 逐卷解析结果
  <source>_<paper_id>_qa.md      # 解析 QA 报告
  raw/                           # OCR / 逐页文本（可选）

data/content/<subject_id>/reports/
  <paper_id>_report.md           # 入库/校验报告
```

### 1.3 源库

```text
data/content/<subject_id>/<subject_id>_exam.db
data/content/<subject_id>/<subject_id>_knowledge.db
```

不要写 `data/releases/`。Release 是构建产物，不可手改。

### 1.4 paper_id

推荐格式：

```text
<subject>-<source>-<year>[-<form>]
```

示例：

```text
psychology-ap-2026
psychology-ap-2026-set-1
psychology-cb-2026-mock-2
psychology-barrons-2027-ch11-review
statistics-barrons-2027-quiz-01
```

要求：

- 全局唯一，且以 `<subject>-` 开头；
- 发布后不要重命名；
- 题目 ID 建议 `<paper_id>-<序号>`，例如 `psychology-ap-2026-001`。

## 2. 开工前准备

### 2.1 已有科目新增一套卷

只需要：

- PDF 路径
- 答案 / 解析 / rubric 路径（如在同一个 PDF 中则说明页码范围）
- `subject_id`
- `paper_id`
- 试卷类型：`real_exam` / `mock_exam` / `unit_practice`
- 年份、Form、Set
- 是否直接写库

### 2.2 全新科目

除 PDF 外，还要先建立：

```text
config/subjects/<subject_id>.json
config/exam_formats/<subject_id>.json
config/practice_topics/<subject_id>.json
config/content_exclusions/<subject_id>.json

data/content/<subject_id>/
  <subject_id>_exam.db
  <subject_id>_knowledge.db
  extraction/
  reports/
```

并确保：

- 源库 schema 与 `docs/content/数据库设计文档.md` 一致；
- `subjects` / `subject_aliases` 有该科目；
- `asset_root` 指向 `assets/<subject_id>`；
- `enabled` 暂时保持 `false`，等内容 QA 通过后再打开。

```text
解析这份 PDF：<路径>
```

需要说明的特殊情况：

| 情况 | 必须说明 |
|---|---|
| 扫描件 / 无文本层 | 需要 OCR |
| 题目和答案分开 | 提供答案文件 |
| FRQ rubric 单独 | 提供 rubric 文件 |
| 选项是图片 | 说明是否接受图片选项 |
| 有题图 / 表格 | 说明图片页码范围 |
| 只想先看质量 | 明确“只 dry-run，不写库” |

## 4. 执行阶段

### Stage 0 — 读规范

```text
prompts/04_pdf_question_ingestion.md
docs/content/试卷解析方法.md
docs/content/数据库设计文档.md
```

如果是新科目，再读：

```text
docs/多科目内容源与合并发布.md
config/subjects/README.md
```

### Stage 1 — 解析 PDF

目标：生成可复核的中间 JSON，不直接写库。

```text
data/content/<subject_id>/extraction/<source>_<paper_id>.json
```

要求：

- 题干、context、选项、答案、解析、题图引用全部保留；
- 记录来源页码 / bbox / 原书答案位置；
- 不编造答案、解析、页码、评分点；
- 选项本身是图片时保留 `option_label` 与 asset 关联；
- FRQ 保留 rubric parts、分值、criteria 全文。

现有脚本是按来源写的，不是通用 PDF 导入器：

| 来源 | 可参考脚本 |
|---|---|
| CB / Barron 心理学 | `parse_cb.py`、`parse_barron_*`、`import_*` |
| Barron 统计 | `stats_parse_questions.py`、`stats_import_questions.py` |
| 新来源 / 新格式 | 新建 `parse_<source>.py` + `import_<source>.py`，或一次性导入脚本 |

> 新 PDF 如果格式差异大，不要硬套旧脚本；先写一个只输出 JSON 的解析器，QA 通过后再写库。

### Stage 2 — QA

输出：

```text
data/content/<subject_id>/reports/<paper_id>_report.md
```

至少检查：

- 题目数 / 选项数 / 答案数对账；
- MCQ 恰好一个正确选项；`correct_answer` 与 `options.is_correct` 一致；
- 选项数 2–5，标签不重复；
- 空选项、缺答案、缺图题有清单；
- 图片文件存在，路径可解析；
- FRQ rubric parts 合计等于 `total_points`；
- `question_id` 唯一，且以 `<paper_id>-` 开头；
- `subject_id` 正确；
- 没有把其他科目的数据写进来。

### Stage 3 — 写源库

写库前：

```bash
cp data/content/<subject_id>/<subject_id>_exam.db \
   data/content/<subject_id>/<subject_id>_exam.db.bak-$(date +%Y%m%d-%H%M%S)-<reason>
```

写库要求：

- 只写 `data/content/<subject_id>/<subject_id>_exam.db`；
- 不写 Release；
- 不删已有试卷；
- 重跑同一 `paper_id` 时先明确是“替换该卷”还是“跳过”；
- 事务提交后跑：

```bash
sqlite3 data/content/<subject_id>/<subject_id>_exam.db \
  "PRAGMA integrity_check; PRAGMA foreign_key_check;"
```

### Stage 4 — 概念关联（可选，但推荐）

```bash
SUBJECT=psychology
EXAM_DB=data/content/$SUBJECT/${SUBJECT}_exam.db
KNOW_DB=data/content/$SUBJECT/${SUBJECT}_knowledge.db

python3 _tools/link_question_concepts.py \
  --paper <paper_id> \
  --exam-db "$EXAM_DB" --know-db "$KNOW_DB" \
  --dry-run --limit 5

python3 _tools/link_question_concepts.py \
  --paper <paper_id> \
  --exam-db "$EXAM_DB" --know-db "$KNOW_DB" \
  --force --workers 3
```

验收：

- `linked / needs_review / no_match` 有报告；
- core 概念 1–2 个；
- 所有 `concept_id` 存在；
- 没有概念的题回落 `question_kp_links`。

### Stage 5 — AI 解析（可选）

只补缺少原书解析的 MCQ：

```bash
python3 _tools/generate_ai_explanations.py \
  --subject psychology \
  --paper <paper_id> \
  --dry-run --limit 3

python3 _tools/generate_ai_explanations.py \
  --subject psychology \
  --paper <paper_id>
```

输出：

```text
data/content/psychology/extraction/ai_explanations_<paper>.json
data/content/psychology/reports/ai_explanation_report.md
```

只写 `options.ai_explanation`，不覆盖 `options.explanation`。

### Stage 6 — 构建 Release

```bash
python3 _tools/build_merged_release.py \
  --release-id content-YYYYMMDD-01
```

构建会自动运行校验。也可以再跑一次：

```bash
python3 _tools/validate_content_release.py \
  --release data/releases/content-YYYYMMDD-01
```

产物：

```text
data/releases/content-YYYYMMDD-01/
  exam.db
  knowledge.db
  assets/
  assets-manifest.json
  release.json
  exclusions.json
```

### Stage 7 — 激活

推荐在 Admin → Release 页面点击“切换到此版本”。

对应接口：

```text
POST /api/v1/admin/releases/{release_id}/activate
```

激活会切换：

```text
data/releases/active
data/releases/current
```

API 下一次请求自动重新加载，不需要重启。

## 5. 交付物清单

一次完整的新 PDF 入库，至少产出：

- [ ] PDF / 答案 / rubric 已放到 `assets/<subject>/papers/`
- [ ] 解析 JSON 在 `data/content/<subject>/extraction/`
- [ ] QA 报告在 `data/content/<subject>/reports/`
- [ ] 源库已写入并备份
- [ ] `PRAGMA integrity_check` / `foreign_key_check` 通过
- [ ] （可选）概念关联报告
- [ ] （可选）AI 解析报告
- [ ] 新 Release 已构建并通过校验
- [ ] 已激活或明确等待激活

---

## 6. 当前自动化边界

- 没有“一份任意 PDF 自动入库”的通用脚本；
- 现有 `parse_*` / `import_*` 脚本按来源和格式编写；
- 新格式需要新增解析器或一次性导入脚本；
- `build_merged_release.py` 负责合并与构建，不负责解析 PDF；
- Release 上传/导入 API 尚未实现（P1.1）。

---

## 7. 禁止事项

- 不要写 `AP_exam/`：目录已移除。
- 不要写根目录 `ap_exam.db` / `ap_knowledge.db`：链接已删除。
- 不要直接改 `data/releases/`：Release 不可变。
- 不要生成 `pages/` 静态页：前端直接读 API/Release。
- 不要把 statistics 数据写进 psychology 源库。
- 不要编造答案、解析、页码、题图、评分点。
- 不要重跑 `strip_to_exam_data.py` / `import_cb_mock.py` 等破坏性 legacy 脚本，除非明确知道后果。
- 不要在未备份、未 dry-run 的情况下直接写源库。
