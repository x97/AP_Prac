# 学习日历（学习计划）

> 状态：已实现
> 相关代码：`apps/api/app/services/study_plans.py`、`apps/api/app/services/homeworks.py`、`apps/web/src/components/study-calendar/`、`apps/admin/src/app/(admin)/study-plans/`

---

## 1. 角色与流程

```text
老师/管理员
  创建课堂作业（Unit/Chapter + MCQ 题目 + 备注）
  → 创建学习计划（多个学习项，每个学习项引用一个课堂作业）
  → 指派给学生（开始日期、结束日期）
  → 系统把学习项均匀排到区间内的每一天
学生
  学习日历 → 点击日期 → 开始当天作业
  → 全部题目答完 → 完成当天任务 → 解锁下一项
```

- 学生端入口：侧边栏「学习日历」`/study-calendar`。
- 管理后台入口：「学习计划」「课堂作业」。
- 一个学生可以同时进行多个学习计划；每个计划独立解锁。
- 课堂作业目前只支持 MCQ；`section` 字段预留 FRQ。

## 2. 数据表（应用库）

| 表 | 用途 |
|---|---|
| `classroom_homeworks` | 可复用的课堂作业模板 |
| `classroom_homework_questions` | 课堂作业题目（有序、去重） |
| `study_plans` | 学习计划模板 |
| `study_plan_items` | 计划内的学习项（引用课堂作业） |
| `study_plan_assignments` | 某个学生的一次计划指派 |
| `study_plan_tasks` | 指派时展开的每日任务快照（月历主查询表） |

关键设计：

- 计划颜色用于学生端区分不同计划：日历格子里的任务标签和右侧任务卡片背景会跟随计划颜色，但不影响任务状态。
- 学生月历只查 `study_plan_tasks`，其中冗余了 `user_id / plan_id / plan_title / plan_color / item_title / homework_title / unit / topic / question_count / day_index / study_date / status`。
- 指派时快照任务；之后修改计划学习项不会改变已生成任务的数量/日期。
- 修改计划标题/颜色/作业标题/备注/单元/章节/题目数时，会刷新**未完成**任务的展示快照。
- 课堂作业题目修改会影响尚未开始的会话；进行中的练习保留自己的题目列表。

## 3. 分配算法

N 个学习项、D 天（含首尾）：

```text
if N == 1: day = 0
else:
  denom = 2 * (N - 1)
  day_i = (2 * i * (D - 1) + (N - 1)) // denom
```

- N=D：每天 1 项。
- N>D：每天项数最多差 1。
- N<D：任务均匀插入，其余为休息/复习空天。
- 同一天多项共享 `day_index`，全部完成才推进。

## 4. 解锁与完成

- 今天及以前未完成的任务都可以直接补做，不要求按顺序补；右侧「待学习」会汇总这些任务。
- 未来日期任务仍需前序任务完成才解锁；完成前一天的任务后，可以提前做未来日期。
- 逾期 = 任务 `status='pending'` 且 `study_date < 今天`（Asia/Shanghai）；在日历上标红，并列入「待学习」。
- 完成 = 当天所有课堂作业的每道 MCQ 都作答；复用 `practice_sessions`，`source="homework"`。
- 全部题目答完后自动交卷，后端回写任务/计划进度；完成回调幂等。
- 老师取消指派后，该计划立即从学生日历消失；已完成记录保留在管理端。

## 5. 管理后台操作

1. 「课堂作业」→ 新建 → 选 Unit/Chapter → 从题库选择题目。
   - 题目选择器默认按章节过滤；支持搜索、来源/试卷/星级筛选、全选当前筛选、预览。
   - 课堂作业被多个计划引用时，编辑页会提示；修改会影响未开始的任务。
2. 「学习计划」→ 新建 → 添加学习项（可多选课堂作业）→ 保存学习项。
3. 计划详情 → 指派学生 → 选开始/结束日期 → 预览每天项数 → 确认。
4. 计划详情查看每个学生的进度、逾期天数，可随时取消某个学生的计划。
5. 学生列表行内也可直接「指派计划」。

## 7. 缓存

- 不缓存月历、日详情、assignment 进度：这些数据随学生完成状态变化，且单表索引查询只有几十行。
- 缓存 release 派生的单元/章节 taxonomy（`ContentStore.list_all_topics`）。
- 课堂作业题目/计划学习项可按 `version` 做进程内缓存（当前实现以直接查询为主，数据量很小）。
- 题目内容继续使用 `ContentStore` 现有缓存；不缓存带签名图片 URL 的题目 payload。

## 8. 老师答疑

只有学习日历课堂作业里的题目支持答疑；普通练习、试卷和错题本没有答疑入口。API 会校验 `practice_sessions.source == "homework"` 且题目在本次会话中。

数据表（`qa_threads` / `qa_replies`）：

- `qa_threads`：每道题下一个学生的一条公开提问。快照 `plan_title / task_title / homework_title / question_stem`，保存 `student_id` 和提问内容。
- `qa_replies`：学生追问与老师回复，`author_type` 为 `student` 或 `teacher`。
- 已读按线程记录：`student_last_read_at / admin_last_read_at`；未读数按 `last_teacher_message_at`、`last_student_message_at` 与该时间比较。
- **只有打开消息详情**（学生 `/qa/{threadId}`、后台 `/qa/{threadId}`）才标记已读；刷新列表或做题页不会清除未读。
- 未读数不做定时轮询：页面打开/路由切换、窗口重新聚焦、阅读详情后各请求一次 `/unread-count`。
- 同一道题的提问对所有做这道题的学生可见；学生只能追问自己的提问。
- 时间字段统一序列化为带 UTC 偏移的 ISO 字符串，前端按浏览器本地时区显示。

接口：

```text
GET  /api/v1/qa/questions/{question_id}?session_id=...
POST /api/v1/qa/questions
POST /api/v1/qa/questions/{question_id}/read?session_id=...
GET  /api/v1/qa/my-threads
GET  /api/v1/qa/threads/{thread_id}
POST /api/v1/qa/threads/{thread_id}/replies
GET  /api/v1/qa/unread-count

GET  /api/v1/admin/qa/threads?subject=&unread=&q=...
GET  /api/v1/admin/qa/threads/{thread_id}
POST /api/v1/admin/qa/threads/{thread_id}/replies
GET  /api/v1/admin/qa/unread-count
```

界面入口：

- 学生做题页：作业题下方 Tab「老师答疑｜我的笔记」，提问与查看其他同学的问题和老师回复。
- 学生 Web：右上角消息铃铛未读数；「我的」和头像菜单进入「老师答疑」列表，每页 20 条，支持上一页/下一页。
- 管理后台：左侧「老师答疑」、顶栏消息铃铛；列表支持全部/未读、搜索学生或内容，详情页回复（支持 Command/Ctrl + Enter）。

## 9. 部署与建表

`infra/compose/docker-compose.yml` 中 API 服务的 `AUTO_CREATE_TABLES=true`，重启 API 会自动创建 8 张新表（6 张学习计划 + 2 张答疑）。若某环境设为 `false`：

```bash
cd apps/api
PYTHONPATH=. ../../.venv/bin/python scripts/create_study_plan_tables.py
```

脚本只新增表，不修改现有表。上线前备份应用库。

## 10. 已知边界

- 课堂作业题目从当前 Release 读取；Release 移除题目时，开始任务会过滤，0 题时返回 `HOMEWORK_CONTENT_UNAVAILABLE`。
- 学习计划任务默认不检查激活码（老师指派即授权）。
- 计划学习项增删不会改变已生成任务；如需调整已指派排期，取消后重新指派。
- 学生时区统一按 Asia/Shanghai；前端日期用 ISO 字符串，避免浏览器时区偏移。
- 答疑只绑定 `source="homework"` 的练习会话；会话交卷后仍可查看/追问，但不能从普通练习页进入。
- 提问与回复对所有做这道题的学生可见；回复中不要包含学生隐私信息。
