# 数据任务操作手册（新同事版）

> 目标：新同事拿到项目后，能快速判断“这个任务该看哪份提示语、跑哪个脚本、改哪些表、验收什么”。  
> 先读：`README.md` → `prompts/README.md` → `docs/content/数据库设计文档.md`。  
> 所有任务都必须先 dry-run / 盘点，再写库；写库前备份。  
> 当前阶段：内容源统一在 `data/content/<subject>/`；`AP_exam/` 已移除。

## 1. 项目目录速查

```text
assets/psychology/            # 静态资源（papers / images / books）

prompts/                      # 所有提示语，统一管理
```

> 根目录不再保留 `ap_exam.db` / `ap_knowledge.db` 兼容链接。

## 3. 新增一套试卷

> 新 PDF 的完整交互模板、目录、阶段和交付物见 [`docs/content/新增试卷解析流程.md`](content/新增试卷解析流程.md)。

### 3.1 用到的提示语

1. `prompts/04_pdf_question_ingestion.md`：解析 PDF、答案、解析、rubric。
2. `prompts/03_question_concept_linking.md`：题目 → 概念。
3. `prompts/05_ai_explanation.md`：缺解析时补 AI 解析（可选）。

### 3.2 用到的脚本

| 步骤 | 脚本 |
|---|---|
| 解析/导入 | `parse_cb.py` / `import_cb_mock.py` / `parse_barron_*` / `import_barron_*`（按来源复制或改造；写 `<subject>_exam.db`） |
| 题目 → 概念 | `link_question_concepts.py`（用 `--exam-db` / `--know-db` 指向科目源库） |
| 权重 | `recompute_concept_weights.py` |
| AI 解析 | `generate_ai_explanations.py --subject <subject_id>` |
| 发布 | `build_merged_release.py`（不再生成静态页面） |

### 3.3 流程

```text
content_sources
→ papers（paper_id = <subject>-<source>-<year>-<form>）
→ staging questions/options/assets/rubrics
→ 答案与解析（官方 > 文中 > AI 推断；AI 只写 ai_explanation）
→ link_question_concepts.py --dry-run
→ link_question_concepts.py --force
→ recompute_concept_weights.py
→ QA（SQL / API）
→ build_merged_release.py
→ 激活 Release
```

示例（psychology）：

```bash
SUBJECT=psychology
EXAM_DB=data/content/$SUBJECT/${SUBJECT}_exam.db
KNOW_DB=data/content/$SUBJECT/${SUBJECT}_knowledge.db

python3 _tools/link_question_concepts.py \
  --paper psychology-ap-2025 \
  --exam-db "$EXAM_DB" --know-db "$KNOW_DB" \
  --dry-run --limit 5

python3 _tools/link_question_concepts.py \
  --paper psychology-ap-2025 \
  --exam-db "$EXAM_DB" --know-db "$KNOW_DB" \
  --force --workers 3

python3 _tools/recompute_concept_weights.py
python3 _tools/build_merged_release.py --release-id content-YYYYMMDD-01
```

### 3.4 写库目标

- 主：`question_concept_links`
- 状态：`question_analysis`
- 关键字：`question_keywords`（含 `concept_id`）
- 兼容：`question_kp_links`（仅 legacy，不要作为新逻辑主表）

### 3.5 验收

- 题目数/选项数/答案数对账
- `linked / needs_review / no_match` 有报告
- core 1–2 个；core 不能只来自干扰项
- 所有 `concept_id` 存在；`question_keywords` 的 surface 能在原文找到
- `integrity_check=ok` / `foreign_key_check=OK`
- 页面重建成功

## 4. 新增一门学科

### 4.1 用到的提示语

1. `prompts/01_book_kp_extraction.md`：每本教材一次。
2. `prompts/02_multi_book_concept_integration.md`：概念层。
3. `prompts/04_pdf_question_ingestion.md`：每套试卷。
4. `prompts/03_question_concept_linking.md`：题目 → 概念。
5. `prompts/05_ai_explanation.md`：AI 解析。

### 4.2 阶段

```text
0. 科目注册：config/subjects/<subject_id>.json + data/content/<subject_id>/
1. 多本教材解析：01 → <subject_id>_knowledge.db
2. 概念层整合：02
3. 题库录入：04 → <subject_id>_exam.db
4. 题目 → 概念：03
5. 权重校准
6. 单元练习配置：config/practice_groups/<subject_id>.json
7. QA
8. 打开 enabled，构建合并 Release 并激活
```

### 4.3 当前缺口（新学科前必须知道）

- `config/subjects/<subject_id>.json` 必须先建好；`exam_formats` / `practice_topics` / `content_exclusions` 三份配置也要补齐（statistics 目前是空占位）。
- `recompute_concept_weights.py` 仍带心理学 `Myers` 加分和 AP unit 判断；新学科要参数化，不能直接套阈值。
- `link_question_concepts.py` 的 `--scope` / `--scope-kind` 可手动指定范围；默认 `infer_scope` 仍是心理学 paper_id 规则，新学科建议显式传 scope，并用 `--exam-db` / `--know-db` 指向科目源库。
- 概念 ID 不跨学科共享；所有查询必须带 `subject_id`。

### 4.4 隔离规则

- 新学科 = 新 `subject_id`。
- 新学科静态资源 = `assets/<subject_id>/`。
- 不要把新学科概念挂到 `psychology` 的 `concept_clusters`。
- 如果未来共享统计/研究方法概念，另建 domain 层，不要直接共享 ID。

## 5. 单元练习虚拟合并

### 5.1 用到的提示语

- `prompts/06_unit_practice_merge.md`：任何学科的单元练习虚拟合并统一规范。
- `prompts/00_data_agent_pipeline.md` 的 Playbook C：总调度和边界说明。
- 单元归属必须以官方课程标准为准，不按教材章节数量平均分配。

### 5.2 用到的脚本

一个学科一个配置：`config/practice_groups/<subject_id>.json`。

```bash
# 先校验，不写库
python3 _tools/merge_unit_practice.py \
  --config config/practice_groups/psychology.json \
  --dry-run

# 正式重建全部 Unit
python3 _tools/merge_unit_practice.py \
  --config config/practice_groups/psychology.json

# 只重建一个 group
python3 _tools/merge_unit_practice.py \
  --config config/practice_groups/psychology.json \
  --group-id psychology-unit1-practice
```

- `config/practice_groups/<subject_id>.json` 的 `exam_db` / `knowledge_db` 必须指向 `data/content/<subject_id>/<subject_id>_exam.db` / `<subject_id>_knowledge.db`。
- 不用 `--config` 的 legacy 模式会按 `--subject-id`（默认 psychology）读取 `config/subjects/<subject_id>.json` 的源库路径。
- 官方题库（CB）固定 `primary`，教材章节固定 `supplement`；脚本按 `primary → supplement → old_edition` 排序。
- 一个 group 恰好一个 primary；没有 primary 时状态为 `needs_review`，不静默把 supplement 升为 primary。
- bundle 只通过 `paper_question_map` 引用原题，不复制 `questions` / `options`。
- `question_fingerprint` 用于检测重复题；先出现的 primary 题保留。
- 脚本会校验 supplement 的概念层主导 `ap_unit` 是否等于目标 Unit；不一致默认阻止写库。
- 配置结构和校验字段见 `config/practice_groups/README.md`。

### 5.3 表

- `practice_groups`
- `practice_group_papers`
- `paper_question_map`（bundle 才写）
- `questions.question_fingerprint`
- `papers`（仅新增 `practice_bundle` 虚拟卷）

### 5.4 当前状态

- 已建 5 个 Unit 组、20 个成员。
- 已建 5 个 `practice_bundle` 虚拟卷，`paper_question_map` 共 1,877 条。
- 修正后的 Bundle 题目数：

| Unit | 成员 | 题目数 |
|---:|---|---:|
| 1 | CB + Barron Ch4–6 | 345 |
| 2 | CB + Barron Ch7–10 | 387 |
| 3 | CB + Barron Ch11–12 | 384 |
| 4 | CB + Barron Ch13–15 | 409 |
| 5 | CB + Barron Ch16–18 | 352 |

- 学生端应只展示 bundle；CB 为主，Barron 作为 supplement 追加，不显示题库选择。
- 当前检测到 5 组跨 Unit 重复 fingerprint（见 `practice_merge_summary.md`），脚本只报告、不自动删除；归属需人工确认。
- 数据层已统一到 bundle；学生端由 API 读取 bundle，不再有静态 unit_practice 页面。

### 5.5 验收

- 成员卷都是 `unit_practice`（或显式 `--allow-any-paper`）
- 每个 active group 恰好一个 primary；没有 primary 的 group 标 `needs_review`
- 同一 paper 不在多个 Unit 重复使用
- 跨 Unit 的重复 fingerprint 有报告；默认 `warn`，不自动删除
- supplement 的 Unit 映射校验通过（或显式 `validation.enabled=false` 并人工核对）
- group/成员数正确
- 重复 fingerprint 报告
- bundle 的 `question_count` = 唯一题数
- `paper_question_map` 的 `source_paper_id` 顺序为 primary 块在前
- `integrity_check` / `foreign_key_check`

## 6. 教材 2027 → 2028

### 6.1 用到的提示语

- `prompts/02_multi_book_concept_integration.md`（`MODE=edition_diff`）
- 受影响题目才需要 `prompts/03_question_concept_linking.md`

### 6.2 用到的脚本

```bash
# 1) 新版抽取/导入（按 01 的流程）
# 2) 结构 diff（只读）
python3 _tools/edition_diff.py \
  --old-book psychology-barrons-2027 \
  --new-book psychology-barrons-2028 \
  --json

# 3) 概念层增量（按 02 的流程）
# 4) 权重重算
python3 _tools/recompute_concept_weights.py
```

### 6.3 规则

- 新版 = 新 `book_id`；同一 `book_family_id`。
- 旧版保留，`books.status='archived'`，不删除。
- 新单元题 = 新 `paper_id`；旧卷保留。
- 题目来源用 `paper_book_sources` / `question_sources`，不要混用“试卷 → 源文件”的 `paper_sources`。
- 概念 ID 跨版本稳定；旧题链接不因换版自动失效。
- 权重的 `cross_book` 按 `COUNT(DISTINCT book_family_id)`，同教材多版本不重复加分。
- 只重链受概念合并/拆分/改定义影响的题。

### 6.4 验收

- `edition_diff_report.md` 的 section/KP/概念变化
- 旧版仍可访问
- 新单元题/新题目有来源
- 受影响题目清单
- 权重变化清单
- `integrity_check` / `foreign_key_check`
- 发布 content release 后，API 的 `content_release_id` 已切换

## 7. 发布到后端（content release）

> 完整设计见 [`内容发布与版本管理.md`](内容发布与版本管理.md)。

数据处理完成、页面重建后，**不要直接让线上 API 读你本地刚改的 SQLite**。走内容发布：

```text
本地内容库 QA
→ data/releases/<release_id>/{release.json, exam.db, knowledge.db, assets-manifest.json}
→ 上传 release + assets
→ POST /internal/content/releases
→ 后端校验、切 active_release
→ smoke test
```

### 最小可行版本

- release 包含新的 `exam.db` + `knowledge.db` 两个文件。
- 后端只读打开 `data/releases/<id>/exam.db` + `knowledge.db`。
- `active_release` 保存 release_id + 文件路径。
- 旧 release 保留，回滚只切指针。
- API 响应带 `content_release_id`。

### 生产推荐

- 内容库放 PostgreSQL 的 `content` schema。
- pipeline 导出 SQL/JSONL，后端导入 `content_staging`。
- 校验 counts/checksum 后原子切换 `active_release_id`。
- 用户库（users/attempts/progress）不受内容发布影响。

### 静态资源

- `assets/psychology/` 是源文件。
- 发布时上传到对象存储/CDN，生成 `assets-manifest.json`。
- API 返回 `asset_url`，不返回本地路径。

### 发布门禁

- 路径缺失 0
- `integrity_check=ok` / `foreign_key_check=OK`
- counts 与 `release.json` 一致
- assets manifest 覆盖所有被引用 asset
- API smoke test：papers / questions / concepts / practice-groups
- 失败不切换 active release

详细设计见 `docs/全栈架构与目录设计.md` 第 10 节。

> 当前实现状态：release 目录规范已定；`publish_content.py` 待后端激活接口确定后实现。在那之前，最小版本可手工打包 `data/releases/<id>/` 并用 `rsync/scp` 同步。

## 9. 统一操作顺序

```text
盘点 → dry-run 计划/diff → staging
→ GATE（结构/概念/关联/权重）
→ 事务写库
→ integrity / FK / 路径
→ 报告
```

任何任务都不要：

- 跳过 dry-run 直接写库
- 用名称直接合并同名异义
- 删除来源 KP
- 把 `question_kp_links` 当作新逻辑主表
- 覆盖官方答案/原书解析
- 移动 DB/静态资源后不更新路径
- 再生成静态刷题页（前端直接读 API/Release）
