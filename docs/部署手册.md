# 部署手册（P0）

## 前置

- 域名 + ICP 备案（提前 2–4 周）+ 公安联网备案。
- 阿里云/腾讯云 2C4G 以上服务器，安装 Docker + Compose。
- 邮箱发信服务（SMTP 账号、发信域名 SPF/DKIM）。
- 生产环境必须设置 `SECRET_KEY`、`COOKIE_SECURE=true`、Postgres `DATABASE_URL`。
- 内容安全相关：`CONTENT_ENCRYPTION_MODE=required`、`ASSET_SIGNING_REQUIRED=true`、`ASSET_SIGNING_KEY`、`RATE_LIMIT_ENABLED=true`。详见 [`内容安全与接口防护.md`](内容安全与接口防护.md)。

> 登录已切换为邮箱 + 密码，微信端另支持微信一键登录。本地用 `EMAIL_PROVIDER=dev`，生产用 `EMAIL_PROVIDER=smtp` 并配置 SMTP。
> P0 用 `AUTO_CREATE_TABLES=true` 建表；已有数据库请先运行 `python scripts/migrate_auth_email.py`。后续改 schema 前请补 Alembic 迁移。


## 测试环境验证码

测试/预发环境不要接真实邮箱，也不要把固定验证码暴露给所有人。推荐：

```env
APP_ENV=staging
EMAIL_PROVIDER=dev
DEV_OTP_CODE=246810
EXPOSE_DEV_OTP=true
```

- `/auth/email/code` 在 dev + `EXPOSE_DEV_OTP=true` 时返回 `debug_code`，登录页会直接显示“测试验证码：246810”。
- 也可以看 API 日志：`DEV email code for ...: 246810`。
- 自动化测试用同一套 dev provider，见 `apps/api/tests/conftest.py`。
- 生产必须 `APP_ENV=prod` + `EMAIL_PROVIDER=smtp` + `EXPOSE_DEV_OTP=false`；`APP_ENV=prod` 且 `EMAIL_PROVIDER=dev` 时 API 会拒绝启动。

## 0. 服务器代码同步（不拉源 PDF）

源 PDF（约 760M）不进 Git，备份到 OSS/NAS；服务器需要题目图片、音频和品牌资源，不需要源 PDF 和 `_archive/`。`.gitignore` / `.gitattributes` 已设置：

```gitignore
assets/**/*.pdf
_archive/
```

```gitattributes
assets/**/*.pdf export-ignore
_archive/** export-ignore
```

`assets/*/images/`、`assets/*/audio/`、`assets/brand/` 和答案 key 等非 PDF 文件会正常进入 Git 和部署包。

### 方式 A：本地 git archive + rsync（推荐）

```bash
SERVER=user@host ./infra/deploy/sync_code.sh
```

脚本用 `git archive` 生成代码包（自动排除 PDF 和 `_archive/`，保留图片/音频），再用 `rsync --delete` 同步到 `/srv/ap-psych`，同时保护服务器上的 `.env`、`releases/`、`backups/`、`certs/`。需要先完成一次 `git commit`。

### 方式 B：服务器已有 git clone，用 sparse-checkout

```bash
cd /srv/ap-psych
git sparse-checkout init --cone
git sparse-checkout set apps config docs infra packages scripts \
  assets/brand assets/psychology/images assets/psychology/audio \
  assets/statistics/images
git sparse-checkout reapply
```

这样源 PDF 和 `_archive/` 不会出现在服务器工作区，题目图片和音频会保留。PDF 本来就不在 Git 里，所以服务器也不会下载它们。注意：`git pull` 仍会更新 Git 对象库；如果连对象都不想下载，新服务器用下面的 partial clone。

### 方式 C：新服务器 partial clone

```bash
git clone --filter=blob:none --sparse <repo-url> /srv/ap-psych
cd /srv/ap-psych
git sparse-checkout set apps config docs infra packages scripts \
  assets/brand assets/psychology/images assets/psychology/audio \
  assets/statistics/images
```

`--filter=blob:none` 只在需要时下载文件内容，进一步减少服务器拉取量。需要远端 Git 服务支持 partial clone（GitHub/GitLab 支持）。

> PDF 备份到 OSS/NAS 即可，不需要给部署脚本提供 OSS/NAS 凭据；备份命令在本机用你自己的 `ossutil` / `rsync` 配置执行，凭据不要写进仓库。

## 1. 构建并校验内容 release

> 完整设计见 [`内容发布与版本管理.md`](内容发布与版本管理.md)：Release 包、上传/导入/激活、Diff、ID 升级、多科目和历史数据。

在本地仓库根目录：

```bash
python3 _tools/build_merged_release.py --release-id content-YYYYMMDD-01
python3 _tools/validate_content_release.py --release data/releases/content-YYYYMMDD-01
```

release 包含 `exam.db`、`knowledge.db`、`assets/`、`assets-manifest.json`、`pronunciation-manifest.json`、`release.json`、`exclusions.json`。如果使用 CDN/对象存储，`assets/` 下的图片和官方卡片发音 mp3 都要上传。

## 2. 上传 release

```bash
export SERVER=user@your-server
export REMOTE_DIR=/srv/ap-psych
rsync -az data/releases/content-YYYYMMDD-01/ "$SERVER:$REMOTE_DIR/releases/content-YYYYMMDD-01/"
ssh "$SERVER" "ln -sfn $REMOTE_DIR/releases/content-YYYYMMDD-01 $REMOTE_DIR/releases/active && ln -sfn $REMOTE_DIR/releases/content-YYYYMMDD-01 $REMOTE_DIR/releases/current"
```

服务器目录：

```text
/srv/ap-psych/
  releases/active -> content-YYYYMMDD-01   # API 优先读取的全局指针
  releases/current -> content-YYYYMMDD-01  # 兼容别名
  releases/content-YYYYMMDD-01/            # 只读，供 API 读取
  infra/compose/                           # docker-compose.yml + .env
  backups/
```

## 3. 环境变量与启动

```bash
cd /srv/ap-psych/infra/compose
cp .env.example .env
# 填写 POSTGRES_PASSWORD、SECRET_KEY、邮箱 SMTP 配置、微信小程序配置
# 内容安全：
#   CONTENT_ENCRYPTION_MODE=required
#   ASSET_SIGNING_REQUIRED=true
#   ASSET_SIGNING_KEY=<独立随机值>
#   RATE_LIMIT_ENABLED=true
#   RATE_LIMIT_PER_MINUTE=600
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1/api/v1/content/version
```

Nginx 默认是 HTTP 配置；HTTPS 用 `infra/deploy/nginx-https.conf.example` 替换 `nginx.conf`，把证书放到 `infra/compose/certs/`，再 `docker compose restart nginx`。

## 4. 备份

```bash
chmod +x /srv/ap-psych/infra/deploy/backup.sh
# crontab -e
# 17 3 * * * /srv/ap-psych/infra/deploy/backup.sh >> /var/log/ap-psych-backup.log 2>&1
```

备份默认保留 7 天；建议再同步到 OSS/COS。

## 5. 发布新 release / 回滚

```bash
# 发布
SERVER=user@host ./infra/deploy/deploy_release.sh content-YYYYMMDD-01

# 回滚：切回旧 release 并重启
ssh "$SERVER" "ln -sfn /srv/ap-psych/releases/<old-release> /srv/ap-psych/releases/active && ln -sfn /srv/ap-psych/releases/<old-release> /srv/ap-psych/releases/current && cd /srv/ap-psych/infra/compose && docker compose restart api worker"
```

保留最近 3–5 个 release；旧 attempt 通过 `content_release_id` 复盘。
