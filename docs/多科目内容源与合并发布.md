# 多科目内容源与合并发布

> 状态：设计定稿（2026-10-30）  
> 适用范围：AP Psychology、AP Statistics，以及后续学科  
> 相关脚本：`_tools/build_merged_release.py`、`_tools/build_exam_configs.py`、`_tools/build_practice_topics.py`、`_tools/build_content_release.py`（legacy）

---

## 0. 结论

采用：

```text
每个科目独立源数据库
        │
        ▼
发布时合并所有 enabled 科目
        │
        ▼
一个 exam.db + 一个 knowledge.db
        │
        ▼
后端始终只读这一套合并后的 Release
```

关键规则：

- 科目源库独立生成、独立编辑。
- 发布时合并成一套 Release。
- 所有科目共用同一个 active Release。
- 所有科目一起发布、一起回滚。
- 后端不再按科目读取不同 Release 文件。
- 用户数据仍然统一放 PostgreSQL。

## 1. 目录结构

```text
data/content/
  psychology/
    psychology_exam.db
    psychology_knowledge.db
    extraction/              # 解析/AI 中间 JSON（可重建，不进 Release）
    reports/                 # 覆盖报告、QA 报告（不进 Release）
    assets/
  statistics/
    statistics_exam.db
    statistics_knowledge.db
    extraction/
    reports/
    assets/
```

只有 `<subject>_exam.db`、`<subject>_knowledge.db` 和 `assets/` 会进入合并 Release；`extraction/` / `reports/` 是本地工作产物，发布时忽略。

科目配置：

```text
config/subjects/
  psychology.json
  statistics.json
```

示例：

```json
{
  "subject_id": "psychology",
  "name": "AP Psychology",
  "name_zh": "AP 心理学",
  "enabled": true,
  "source_dir": "data/content/psychology",
  "exam_db": "psychology_exam.db",
  "knowledge_db": "psychology_knowledge.db",
  "asset_root": "assets/psychology",
  "exam_config": "config/exam_formats/psychology.json",
  "practice_topics": "config/practice_topics/psychology.json",
  "exclusions": "config/content_exclusions/psychology.json"
}
```

规则：

- 一个科目只写自己的 `<subject>_exam.db` / `<subject>_knowledge.db`。
- 不要把多个科目的数据混写进一个源库。
- 源库中的 `subject_id` 必须与本目录一致。
- 跨科目 ID 必须全局唯一，推荐统一加 `<subject>-` 前缀。
- `enabled=false` 的科目不参与合并发布。

当前：

- psychology：enabled
- statistics：暂时 disabled，等概念层完成后启用

## 2. Release 结构

所有 enabled 科目合并成一个 Release：

```text
data/releases/content-YYYYMMDD-NNN/
  exam.db
  knowledge.db
  assets/
    psychology/...
    statistics/...
  assets-manifest.json
  release.json
  exclusions.json
```

Release ID 使用：

```text
content-YYYYMMDD-NNN
```

active 只有一个全局指针：

```text
data/releases/active -> content-YYYYMMDD-NNN
```

`release.json`：

```json
{
  "release_id": "content-20261030-01",
  "subjects": ["psychology", "statistics"],
  "schema_version": 1,
  "counts_by_subject": {
    "psychology": {"questions": 2876, "concepts": 1105},
    "statistics": {"questions": 613, "concepts": 0}
  },
  "counts": {"questions": 3489, "concepts": 1105},
  "checksums": {
    "exam.db": "sha256:...",
    "knowledge.db": "sha256:...",
    "assets-manifest.json": "sha256:..."
  }
}
```

## 3. 构建流程

```text
读取 config/subjects/*.json
  → 取 enabled 科目
  → 复制每个科目源库到 staging
  → 对每个科目生成派生表
  → 合并 exam.db / knowledge.db
  → 合并 assets
  → 生成 manifest / release.json
  → 校验
  → 生成不可变 Release
```

脚本：

```bash
python _tools/build_merged_release.py \
  --release-id content-20261030-01
```

干跑：

```bash
python _tools/build_merged_release.py \
  --release-id content-test-001 \
  --dry-run
```

## 5. 合并规则

### 5.1 先主表，后关联表

合并必须保持依赖顺序：

```text
subjects
paper_types
papers
questions
options
assets
frq_rubrics
rubric_parts
paper_question_map
paper_sources
paper_book_sources
question_sources
content_sources
practice_groups
practice_group_papers
practice_topics
practice_topic_questions
practice_topic_concepts
paper_exam_configs
question_display
question_exclusions
```

知识库：

```text
subjects
subject_aliases
books
sections
section_texts
section_researchers
knowledge_points
concept_clusters
concept_members
concept_relations
kp_aliases
kp_experiments
kp_relations
kp_researchers
question_analysis
question_concept_links
question_keywords
question_kp_links
```

### 5.2 ID 唯一

合并前必须检查：

- `paper_id`
- `question_id`
- `concept_id`
- `kp_id`
- `book_id`
- `topic_id`
- `group_id`

冲突时拒绝发布。

### 5.3 外键和孤儿

合并后执行：

```sql
PRAGMA integrity_check;
PRAGMA foreign_key_check;
```

并检查：

- question → paper
- option → question
- asset → question
- rubric → question
- concept link → question/concept
- topic question → topic/question
- 每个科目 counts 与 release.json 一致

### 5.4 不进入 Release 的表

以下生产审计表可以留在源库，不合并进 Release：

- `ingestion_runs`
- `validation_issues`
- `pipeline_runs` / `pipeline_steps`
- 其他只用于本地 QA 的表

## 6. 后端

后端只读：

```text
data/releases/active/exam.db
data/releases/active/knowledge.db
```

`/subjects` 从合并后的 `subjects` 表返回。

内容请求：

```text
/api/v1/papers?subject=psychology
/api/v1/papers?subject=statistics
```

`ContentStore` 用同一套合并 DB，按 `subject_id` 过滤。

资产：

```text
/assets/psychology/...
/assets/statistics/...
```

一个 Release 的 assets 根目录同时包含所有科目。

用户数据：

```text
PostgreSQL
  users
  attempts
  practice_sessions
  answers
  wrong_questions
  notes
  ...
```

不按科目拆 PostgreSQL。

## 7. 发布与回滚

发布：

```text
所有 enabled 科目一起构建
→ 合并
→ 校验
→ 生成一个 Release
→ 切换 active
```

回滚：

```text
切回上一个 content-YYYYMMDD-NNN
```

限制：

- 不能单独发布一个科目
- 不能单独回滚一个科目
- 一个科目校验失败会阻塞整包发布

这是合并方案的明确代价。

Admin 激活接口：

```text
POST /api/v1/admin/releases/{release_id}/activate
```

- 只切换一个全局 `data/releases/active` 符号链接。
- 从 `release.json` 的 `subjects` 读取本次同时切换的科目。
- `content_releases` / `content_active_release` 按科目各写一行，便于审计和旧接口兼容。
- P1.0 的 `data/releases/active/<subject>` 目录布局会在激活时自动迁移；只有当目录内全部是符号链接时才自动删除，否则返回 409 要求人工处理。

当前旧结构：




- psychology 和 statistics 已从旧的合并源库拆分。

- statistics 概念层完成后，再补齐配置并将 `config/subjects/statistics.json` 改为 true。

## 11. 注意

- 合并 Release 不是“把三份 DB 直接拼成一个文件”这么简单，必须先统一 schema、检查 ID、检查外键。
- 新增科目时，先确保该科目源库通过独立校验，再打开 `enabled`。
- 所有科目一起发布；不要把“单科发布”当作当前能力。
