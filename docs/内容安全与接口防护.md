# 内容安全与接口防护

> 状态：P1 + P2 已实现，P3 内容 payload 加密已实现。  
> 目标：降低题库被未登录访问、批量抓取、图片盗链和简单脚本抓取的风险。

---

## 0. 先说边界

前端能解密的内容，登录用户最终一定能拿到明文。应用层加密只能：

- 避免响应明文出现在代理日志、调试日志里；
- 提高 curl / 简单脚本抓取的门槛；
- 配合限流、鉴权、签名资源，降低批量抓取效率。

它不能阻止：

- 用户打开 DevTools 查看已解密数据；
- 截图、录屏、人工抄题；
- 拥有合法账号的人抓取自己有权限的题目。

真正有效的是：

```text
考试中不下发答案 / 解析 / rubric
+ 登录鉴权
+ attempt 归属校验
+ 限流
+ 私有签名资源
```

## 1. 已实现

### 1.1 内容接口强制登录

以下接口不再允许匿名访问：

```text
GET /api/v1/papers
GET /api/v1/papers/{paper_id}
GET /api/v1/practice-groups
GET /api/v1/practice-groups/{group_id}
GET /api/v1/practice-groups/{group_id}/topics
GET /api/v1/practice-groups/{group_id}/topics/{topic_id}
```

仍公开：

```text
GET /healthz
GET /readyz
GET /api/v1/content/version
GET /api/v1/subjects
```

### 1.2 全局限流

`app/core/rate_limit.py` 同时按 session cookie 和 IP 做滑动窗口限流：

```text
每个 session：600 次/分钟
每个 IP：1200 次/分钟
```

可通过环境变量调整：

```text
RATE_LIMIT_ENABLED=true
RATE_LIMIT_PER_MINUTE=600
```

返回：

```json
{"code":"RATE_LIMITED","message":"请求过于频繁，请稍后再试"}
```

并带 `Retry-After`。

当前是单进程内存实现；多 worker / 多实例生产环境应替换为 Redis 版本。

### 1.3 缓存与安全头

所有 `/api/` 响应默认：

```text
Cache-Control: private, no-store
Pragma: no-cache
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
X-Frame-Options: DENY
```

### 1.4 内容 payload 加密

只对以下前缀的 JSON 响应加密：

```text
/api/v1/attempts
/api/v1/practice-sessions
/api/v1/practice-groups
/api/v1/papers
/api/v1/me
/api/v1/flashcards
/api/v1/question-reports
```

协议：

```text
浏览器生成 P-256 临时密钥对（内存缓存 10 分钟）
→ 请求头 X-Content-Pubkey: base64(raw public key)
→ 服务端生成临时 P-256 密钥对
→ ECDH 共享密钥
→ HKDF-SHA256(salt, info="ap-content-v1") 派生 AES-256 key
→ AES-256-GCM 加密 JSON
→ 返回 envelope
```

请求头：

```text
X-Content-Pubkey: <base64 uncompressed P-256 public key>
```

响应 envelope：

```json
{
  "encrypted": true,
  "v": 1,
  "alg": "ECDH-P256+HKDF-SHA256+AES-256-GCM",
  "server_public_key": "base64",
  "salt": "base64",
  "iv": "base64",
  "ciphertext": "base64"
}
```

AAD：

```text
ap-content-v1|<METHOD>|<PATH>
```

前端用 WebCrypto 解密，密钥只放内存，不写 `localStorage`。

配置：

```text
CONTENT_ENCRYPTION_MODE=off|optional|required
CONTENT_ENCRYPTION_PREFIXES=/api/v1/attempts,/api/v1/practice-sessions,/api/v1/practice-groups,/api/v1/papers,/api/v1/knowledge-graph,/api/v1/me,/api/v1/flashcards,/api/v1/question-reports
```

- `off`：不加密；
- `optional`：客户端带公钥才加密（默认，方便滚动发布）；
- `required`：上述前缀必须带公钥，否则 428。

> 直接用浏览器地址栏、curl 或 Postman 打开这些接口时，不会自动带 `X-Content-Pubkey`，因此在 `optional` 模式下看到的是明文。  
> 前端 `apps/web` 会自动带公钥；生产环境应设 `required`，这样没有公钥的请求会直接返回 428，而不是明文。

生产建议：

```text
CONTENT_ENCRYPTION_MODE=required
```

### 1.5 图片签名 URL

Release assets 不再由 Nginx 直接公开目录。

`ContentStore.asset_url()` 返回：

```text
/assets/psychology/images/...?exp=<unix>&sig=<hmac>
```

签名：

```text
HMAC-SHA256(secret, "<path>|<exp>")
```

API 路由 `GET /assets/{path}` 校验：

- 未过期；
- 签名匹配；
- 路径不逃逸出 active Release 的 `assets/` 根目录。

配置：

```text
ASSET_SIGNING_REQUIRED=true
ASSET_SIGNING_KEY=<独立随机密钥，留空则使用 SECRET_KEY>
ASSET_URL_TTL_SECONDS=7200
```

Nginx 必须把 `/assets/` 代理给 API，不能再用 `alias` 直出，否则签名校验会被绕过。

### 1.6 邮箱验证码限流

验证码发送已有：

```text
同邮箱 1 次/分钟
同邮箱 5 次/小时
同 IP 20 次/小时
验证码最多尝试 5 次
验证码 5 分钟过期，成功后立即作废
```

可通过 `OTP_EMAIL_PER_MINUTE` / `OTP_EMAIL_PER_HOUR` / `OTP_IP_PER_HOUR` / `OTP_TTL_SECONDS` / `OTP_MAX_ATTEMPTS` 调整。

验证码哈希绑定了 `purpose`（register / reset / bind_email），注册验证码不能用于重置密码。

## 2. 前端实现

`apps/web/src/lib/api.ts` 对所有 secure prefix 请求自动：

1. 复用内存缓存的 P-256 ECDH 密钥对（10 分钟）；
2. 发送 `X-Content-Pubkey`；
3. 收到 `X-Content-Encrypted: 1` 后解密；
4. 解密失败抛 `ApiError`，不回退明文。

适用范围：

- 试卷列表 / 试卷详情；
- 考试 attempt；
- 练习 session；
- 错题本 / 收藏 / 笔记 / 做题记录；
- 记忆卡片 / 自定义卡片；
- 题目报错。

不加密：

- 登录 / OTP；
- `/me`；
- 错题本 / 笔记 / 收藏；
- Admin 接口。

## 5. 验证

后端测试覆盖：

- 未登录访问内容接口返回 401；
- 加密请求返回 `X-Content-Encrypted: 1`，客户端可解出 11 套试卷；
- 非法公钥返回 400；
- 签名 asset URL 返回 200，篡改签名返回 403。

本地手工：

```bash
curl -s http://127.0.0.1:8000/api/v1/papers
# 401

curl -s -H "X-Content-Pubkey: invalid" \
  http://127.0.0.1:8000/api/v1/papers
# 400 CONTENT_KEY_INVALID
```
